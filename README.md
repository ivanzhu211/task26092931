# DeskBridge 远程支持会话协调库

Go 进程内库，由上层直接调用，状态全部保存在内存中。协调远程支持会话的
建立、转交、撤回与结束，保证并发下不突破技师容量、迟到结果不改变归属。

## 核心规则

- 每名技师最多 3 个名额（`NewCoordinator` 可调整）。进行中的会话、待决建立、
  待决转入均计入；待决转出仍占原技师名额。
- 建立与转交均异步执行调用方提供的 `PrepareFunc`（`func() bool`）。
  受理与否立即返回；容量不足立即拒绝且不执行准备函数，无排队。
- 转交成功时归属切换、原名额释放、目标预占转正同时生效；失败仅撤销目标预占。
- 每次受理的转交返回独立 `TransferID`，可单独撤回；撤回后立即释放目标预占，
  可再次向同一目标申请。旧申请的迟到结果一律忽略。
- 结束会话立即成为终态，释放全部占用与预占；会话编号不可复用。
- `Snapshot` 在单次持锁内生成，归属、待决申请与名额对应同一时刻。

## 使用示例

```go
c := deskbridge.NewCoordinator(3) // 每名技师 3 个名额；<=0 用默认值

// 建立会话：受理即返回，准备函数在后台执行
ok := c.Establish("sess-1", "tech-a", func() bool {
    return dialUserDevice() // 可能很慢；失败会自动释放预占名额
})

// 转交会话：目标必须不同于当前技师，同一会话仅允许一个待决转交
tid, ok := c.Transfer("sess-1", "tech-b", func() bool {
    return prepareReceiver()
})

// 撤回本次转交（幂等）；之后可向同一目标重新申请
c.CancelTransfer("sess-1", tid)

// 结束会话（幂等），立即释放名额，不等待准备函数退出
c.EndSession("sess-1")

// 整体查看：会话归属、待决申请与各技师已用名额，同一时刻自洽
snap := c.Snapshot()
for id, s := range snap.Sessions { /* ... */ }
used := snap.TechUsed["tech-a"]
```

## 测试

```sh
go test -race -count=1 ./...
```

覆盖：并发争抢最后名额（被拒申请不执行准备函数）、撤回后同目标重试与迟到
结果隔离、待决期间结束后迟到成功不复活会话、阻塞准备函数下各操作 200ms 内
返回、64 并发混合操作下快照逐项核对一致。
