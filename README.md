# DeskBridge 远程支持会话协调库

进程内会话协调库，由上层直接调用，状态保存在内存中。每名技师最多同时承担
3 个名额：进行中的会话、待决建立与待决转入均计入；待决转出仍占原技师名额。

## 构建与测试

```sh
go build ./...
go test -race -count=1 ./...
```

## 调用说明

```go
c := deskbridge.NewCoordinator()

// 建立会话：受理即预占技师一个名额，准备函数在后台 goroutine 执行，
// 调用方无需等待准备完成。容量不足立即返回 ErrCapacityFull，且不执行准备函数。
err := c.Establish("session-1", "tech-a", func() bool {
    return doSlowPrepare() // 仅返回成功/失败，可长期阻塞
})

// 转交会话：目标必须不同于当前技师；受理即预占目标名额，原归属不变。
// 返回本次申请编号，用于撤回。同一会话仅允许一个待决转交。
transferID, err := c.Transfer("session-1", "tech-b", prepFunc)

// 撤回指定转交：立即释放目标预占，可随后向同一目标重试；
// 旧申请的迟到结果不会影响新申请。重复撤回无副作用。
c.CancelTransfer("session-1", transferID)

// 结束会话：立即成为终态，释放正式占用与全部有效预占，不等待准备函数。
// 重复结束无副作用；结束后编号不可重新建立。
c.EndSession("session-1")

// 整体查看：同一时刻的一致性快照，名额由会话与有效预占逐项统计得出。
snap := c.Snapshot()
for id, s := range snap.Sessions { /* 归属、状态、待决转交 */ }
for tech, used := range snap.TechSlots { /* 已用名额 */ }
```

## 关键语义

- 准备函数仅返回成功或失败，不修改库内状态；库在后台执行并在结果到达时
  原子生效。迟到结果（已撤回/已结束/已被新申请取代）一律忽略。
- 转交准备成功时，归属切换、原技师名额释放、目标预占转为正式占用在同一把
  锁内同时生效；失败仅撤销目标预占。
- 结束后的会话编号不可复用（`ErrSessionEnded`）；建立失败则释放名额，
  允许以相同编号重新申请。
- 所有受理类操作（建立/转交/撤回/结束/查看）只持锁做内存记账，准备函数在
  锁外执行，因此阻塞的准备函数不会拖住任何其他操作。
